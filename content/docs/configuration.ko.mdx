## 서버 구성 (beacon)

CLI 플래그 또는 환경 변수를 사용합니다. 기준이 되는 레퍼런스는 다음입니다:

```bash
beacon serve --help
```

### 핵심 옵션

| 옵션 | Env | 기본값 | 비고 |
|---|---|---|---|
| `--database-url` | `DATABASE_URL` | `sqlite://./beacon_auth.db?mode=rwc` | 기본은 SQLite입니다. |
| `--bind-address` | `BIND_ADDRESS` | `127.0.0.1:8080` | HTTP 바인드 주소. |
| `--control-socket` | `CONTROL_SOCKET` | `beacon-auth` (Windows) / `/tmp/beacon-auth.sock` (Unix) | 로컬 관리 작업용 컨트롤 소켓. |
| `--cors-origins` | `CORS_ORIGINS` | `http://localhost:3000,http://localhost:5173` | 콤마로 구분합니다. |
| `--jwt-expiration` | `JWT_EXPIRATION` | `3600` | 액세스 토큰 만료(초). |
| `--log-level` | `RUST_LOG` | `info` | 로그 레벨 필터. |
| `--base-url` | `BASE_URL` | `https://beaconauth.pages.dev` | issuer, OAuth 리다이렉트, WebAuthn RP origin에 사용됩니다. |
| `--jwt-kid` | `JWT_KID` | `beacon-auth-key-1` | JWT `kid` 헤더 값. |
| `--redis-url` | `REDIS_URL` | _(empty)_ | WebAuthn 세레모니 상태를 위한 선택적 Redis. |
| `--jwks-url` | `JWKS_URL` | _(empty)_ | `jku` 용으로 광고할 JWKS URL(선택). |

### OAuth 옵션

| 옵션 | Env | 비고 |
|---|---|---|
| `--github-client-id` | `GITHUB_CLIENT_ID` | GitHub OAuth client ID. |
| `--github-client-secret` | `GITHUB_CLIENT_SECRET` | GitHub OAuth client secret. |
| `--google-client-id` | `GOOGLE_CLIENT_ID` | Google OAuth client ID. |
| `--google-client-secret` | `GOOGLE_CLIENT_SECRET` | Google OAuth client secret. |
| `--microsoft-client-id` | `MICROSOFT_CLIENT_ID` | Microsoft Entra ID client ID. |
| `--microsoft-client-secret` | `MICROSOFT_CLIENT_SECRET` | Microsoft Entra ID client secret. |
| `--microsoft-tenant` | `MICROSOFT_TENANT` | 기본값은 `common` 입니다. |

### 관리용 명령

```bash
beacon migrate --database-url sqlite://./beacon_auth.db
beacon create-user --username admin --password your_password
beacon list-users
beacon delete-user --username admin
```

### 예시 `.env`

``` bash
DATABASE_URL=sqlite://./beacon_auth.db?mode=rwc
BIND_ADDRESS=0.0.0.0:8080
CORS_ORIGINS=http://localhost:3000,http://localhost:5173
JWT_EXPIRATION=3600
RUST_LOG=info
BASE_URL=https://auth.example.com
JWT_KID=beacon-auth-key-1

# Optional
REDIS_URL=
JWKS_URL=

# OAuth providers
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
MICROSOFT_CLIENT_ID=
MICROSOFT_CLIENT_SECRET=
MICROSOFT_TENANT=common
```

## Cloudflare Worker 구성

Worker는 `wrangler.workers.jsonc` 및 배포 시점 변수로 설정합니다.

### `wrangler.workers.jsonc` 에 정의되는 변수

| 변수 | 목적 |
|---|---|
| `LIBSQL_URL` | libSQL/Turso DB 엔드포인트. |
| `BASE_URL` | issuer + OAuth 리다이렉트에 사용할 공개 base URL. |
| `JWKS_URL` | 선택적으로 광고할 JWKS URL. |
| `JKU_ALLOWED_HOST_PATTERNS` | JWT `jku` fetch 에 허용할 호스트 패턴. |
| `JWT_KID` | 헤더의 JWT key id. |
| `ACCESS_TOKEN_EXPIRATION` | 액세스 토큰 수명(초). |
| `REFRESH_TOKEN_EXPIRATION` | 리프레시 토큰 수명(초). |
| `JWT_EXPIRATION` | 일반 JWT 만료(초). |

### 시크릿 (Worker)

배포 워크플로는 필요에 따라 아래 시크릿을 동기화할 수 있습니다:

- `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
- `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`, `MICROSOFT_TENANT`
- `LIBSQL_AUTH_TOKEN` (libSQL/Turso용)

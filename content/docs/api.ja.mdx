## ベースパス

API は以下で提供されます:

- `/v1/*`（直接）
- `/api/v1/*`（`/api` 配下にマウントした場合）

## 主要エンドポイント

### セッション

- `POST /v1/login`
- `POST /v1/register`
- `POST /v1/refresh`
- `POST /v1/logout`
- `GET /v1/user/me`
- `GET /v1/user/me/avatar`
- `POST /v1/user/change-password`
- `POST /v1/user/change-username`
- `POST /v1/user/profile`

例: `POST /v1/login`

```json
{
  "username": "player123",
  "password": "secure_password"
}
```

### Minecraft 認証 (OIDC)

Minecraft mod は標準の OIDC 認可コード + PKCE フローを使用します:

- `GET /.well-known/openid-configuration` — OIDC discovery
- `GET /v1/oidc/authorize` — 認可エンドポイント（mod がログイン UI 経由で開きます）
- `POST /v1/oidc/complete` — SPA が認可を完了し、mod にリダイレクトします
- `POST /v1/oidc/token` — トークンエンドポイント（クライアントシークレットなし、PKCE バインド）
- `GET /v1/oidc/userinfo` — userinfo エンドポイント（アクセストークン認可）

### Minecraft identity

Mojang 検証済みのプレミアムプレイヤーがオンラインモードバイパスで接続するとき、mod は Mojang UUID が
BeaconAuth アカウントに紐づいているか、その身元をどう解決するかを確認できます:

- `GET /v1/minecraft/lookup?uuid=<mojangUuid>` — `X-Minecraft-Auth` 共有シークレット
  （`MINECRAFT_LOOKUP_SECRET`）で認証。`{ bound, identity_mode, user_subject, textures_value,
  textures_signature }` を返します。
- `GET /v1/minecraft/identity-mode` — 現在のユーザーの有効な身元プリファレンス。
- `POST /v1/minecraft/identity-mode` — 現在のユーザーのプリファレンス（`mojang`/`legacy`）を設定。

### OAuth

- `POST /v1/oauth/start`
- `POST /v1/oauth/link/start`
- `GET /v1/oauth/callback`

対応プロバイダー: `github`, `google`, `microsoft`（Entra ID）、`minecraft`（Microsoft コンシューマー +
Xbox。`MICROSOFT_CLIENT_ID`/`MICROSOFT_CLIENT_SECRET` を再利用）。`minecraft` プロバイダーは実際の
Mojang UUID をプロバイダー身元としてバインドします。

### パスキー（WebAuthn）

- `POST /v1/passkey/register/start`
- `POST /v1/passkey/register/finish`
- `POST /v1/passkey/auth/start`
- `POST /v1/passkey/auth/finish`
- `POST /v1/passkey/delete`
- `GET /v1/passkey/list`
- `DELETE /v1/passkey/{id}`

### アイデンティティ

- `GET /v1/identities`
- `DELETE /v1/identities/{id}`

### 設定と JWKS

- `GET /v1/config`
- `GET /.well-known/jwks.json`

### 管理

- `POST /v1/admin/migrations/up`

## メモ

- セッション系エンドポイントは access/refresh 用の HttpOnly cookie を設定します。
- JWT は ES256 で署名され、JWKS で公開されます。
- 一部のエンドポイントは認証済みセッションが必要です。

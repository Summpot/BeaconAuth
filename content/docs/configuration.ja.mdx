## サーバー設定（beacon）

CLI フラグまたは環境変数で設定します。最も正確な参照は次です:

```bash
beacon serve --help
```

### 主要オプション

| Option | Env | Default | Notes |
|---|---|---|---|
| `--database-url` | `DATABASE_URL` | `sqlite://./beacon_auth.db?mode=rwc` | 既定は SQLite。 |
| `--bind-address` | `BIND_ADDRESS` | `127.0.0.1:8080` | HTTP バインドアドレス。 |
| `--control-socket` | `CONTROL_SOCKET` | `beacon-auth` (Windows) / `/tmp/beacon-auth.sock` (Unix) | ローカル管理用の制御ソケット。 |
| `--cors-origins` | `CORS_ORIGINS` | `http://localhost:3000,http://localhost:5173` | カンマ区切り。 |
| `--jwt-expiration` | `JWT_EXPIRATION` | `3600` | アクセストークンの有効期限（秒）。 |
| `--log-level` | `RUST_LOG` | `info` | ログレベル。 |
| `--base-url` | `BASE_URL` | `https://beaconauth.pages.dev` | Issuer、OAuth リダイレクト、WebAuthn RP origin に使用。 |
| `--jwt-kid` | `JWT_KID` | `beacon-auth-key-1` | JWT ヘッダー `kid` の値。 |
| `--redis-url` | `REDIS_URL` | _(empty)_ | WebAuthn の ceremony state 用に Redis（任意）。 |
| `--jwks-url` | `JWKS_URL` | _(empty)_ | `jku` 用に告知する JWKS URL（任意）。 |

### OAuth オプション

| Option | Env | Notes |
|---|---|---|
| `--github-client-id` | `GITHUB_CLIENT_ID` | GitHub OAuth クライアント ID。 |
| `--github-client-secret` | `GITHUB_CLIENT_SECRET` | GitHub OAuth クライアントシークレット。 |
| `--google-client-id` | `GOOGLE_CLIENT_ID` | Google OAuth クライアント ID。 |
| `--google-client-secret` | `GOOGLE_CLIENT_SECRET` | Google OAuth クライアントシークレット。 |
| `--microsoft-client-id` | `MICROSOFT_CLIENT_ID` | Microsoft Entra ID クライアント ID。 |
| `--microsoft-client-secret` | `MICROSOFT_CLIENT_SECRET` | Microsoft Entra ID クライアントシークレット。 |
| `--microsoft-tenant` | `MICROSOFT_TENANT` | 既定は `common`。 |

### 管理コマンド

```bash
beacon migrate --database-url sqlite://./beacon_auth.db
beacon create-user --username admin --password your_password
beacon list-users
beacon delete-user --username admin
```

### `.env` 例

``` bash
DATABASE_URL=sqlite://./beacon_auth.db?mode=rwc
BIND_ADDRESS=0.0.0.0:8080
CORS_ORIGINS=http://localhost:3000,http://localhost:5173
JWT_EXPIRATION=3600
RUST_LOG=info
BASE_URL=https://auth.example.com
JWT_KID=beacon-auth-key-1

# Optional
REDIS_URL=
JWKS_URL=

# OAuth providers
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
MICROSOFT_CLIENT_ID=
MICROSOFT_CLIENT_SECRET=
MICROSOFT_TENANT=common
```

## Cloudflare Worker 設定

Worker は `wrangler.workers.jsonc` とデプロイ時変数で設定します。

### `wrangler.workers.jsonc` で定義される変数

| Variable | Purpose |
|---|---|
| `LIBSQL_URL` | libSQL/Turso データベースのエンドポイント。 |
| `BASE_URL` | Issuer + OAuth リダイレクト用の公開 Base URL。 |
| `JWKS_URL` | 告知する JWKS URL（任意）。 |
| `JKU_ALLOWED_HOST_PATTERNS` | JWT `jku` フェッチで許可するホスト。 |
| `JWT_KID` | JWT の key id。 |
| `ACCESS_TOKEN_EXPIRATION` | Access token の有効期限（秒）。 |
| `REFRESH_TOKEN_EXPIRATION` | Refresh token の有効期限（秒）。 |
| `JWT_EXPIRATION` | 一般的な JWT の有効期限（秒）。 |

### Secrets（Worker）

デプロイワークフローは、以下の secrets を同期できます:

- `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
- `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`, `MICROSOFT_TENANT`
- `LIBSQL_AUTH_TOKEN`（libSQL/Turso 用）

## 概要

BeaconAuth は分割デプロイをサポートします:

- **Cloudflare Pages**: React UI
- **Cloudflare Worker**（`crates/beacon-worker`）: API

両方のデプロイは `wrangler.jsonc` と `wrangler.workers.jsonc` の `name`（プロジェクト名）を
一致させる必要があります（CI が検証します）。

## Wrangler 設定

- `wrangler.jsonc`: Cloudflare Pages 設定（UI 出力は `dist/`）
- `wrangler.workers.jsonc`: Cloudflare Worker 設定（wasm 出力）

## CI ワークフロー

- `.github/workflows/deploy-cloudflare-pages.yml`: UI をデプロイ
- `.github/workflows/deploy-cloudflare-worker.yml`: API Worker をデプロイし migrations を適用

### 必須 secrets（Pages）

- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`

任意:

- `SENTRY_AUTH_TOKEN`

### 必須 secrets（Worker）

- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`
- `TURSO_PLATFORM_API_TOKEN`
- `TURSO_ORG_SLUG`
- `TURSO_DB_NAME`

任意:

- `TURSO_GROUP`（既定は `default`）
- `CLOUDFLARE_WORKER_BASE_URL`（既定は `https://<name>.pages.dev`）
- `CLOUDFLARE_WORKER_LIBSQL_URL`（Turso API の代わりに libSQL URL を指定）
- `CLOUDFLARE_WORKER_LIBSQL_AUTH_TOKEN`
- `CLOUDFLARE_MIGRATIONS_API_TOKEN`（`/v1/admin/migrations/up` 用）
- OAuth provider secrets（下記参照）

### OAuth 用の任意 Worker secrets

- `CLOUDFLARE_WORKER_GITHUB_CLIENT_ID`
- `CLOUDFLARE_WORKER_GITHUB_CLIENT_SECRET`
- `CLOUDFLARE_WORKER_GOOGLE_CLIENT_ID`
- `CLOUDFLARE_WORKER_GOOGLE_CLIENT_SECRET`
- `CLOUDFLARE_WORKER_MICROSOFT_CLIENT_ID`
- `CLOUDFLARE_WORKER_MICROSOFT_CLIENT_SECRET`
- `CLOUDFLARE_WORKER_MICROSOFT_TENANT`

## Single-origin ルーティング（任意）

UI と API を同一オリジンにしたい場合、このリポジトリは Nitro の server entry で対応しています。

- server entry は `src/server.ts` にあります。
- Nitro はビルド時に Cloudflare Pages worker bundle（`_worker.js`）を自動生成します。
	Pages 用の手動 entry ファイルは不要です。
- Pages プロジェクトに `BACKEND` という service binding を作成し、API Worker を指すようにしてください
	（`wrangler.jsonc` を参照）。

既定では、`/api/`・`/v1/`・`/.well-known/` で始まるパスを `env.BACKEND` にプロキシし、それ以外は UI を返します。

## メモ

- Worker デプロイは libSQL/Turso を使用します（`LIBSQL_URL` と `LIBSQL_AUTH_TOKEN` を設定）。
- migrations は CI で Worker の `POST /v1/admin/migrations/up` から適用されます。

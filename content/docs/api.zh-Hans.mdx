## 基础路径

API 可通过以下路径访问：

- `/v1/*`（直接访问）
- `/api/v1/*`（挂载在 `/api` 下时）

## 核心端点

### 会话

- `POST /v1/login`
- `POST /v1/register`
- `POST /v1/refresh`
- `POST /v1/logout`
- `GET /v1/user/me`
- `GET /v1/user/me/avatar`
- `POST /v1/user/change-password`
- `POST /v1/user/change-username`
- `POST /v1/user/profile`

示例：`POST /v1/login`

```json
{
  "username": "player123",
  "password": "secure_password"
}
```

### Minecraft 认证（OIDC）

Minecraft 模组使用标准的 OIDC authorization-code + PKCE 流程：

- `GET /.well-known/openid-configuration` — OIDC 发现
- `GET /v1/oidc/authorize` — 授权端点（模组通过登录界面打开）
- `POST /v1/oidc/complete` — SPA 完成授权，重定向回模组
- `POST /v1/oidc/token` — 令牌端点（无客户端密钥，PKCE 绑定）
- `GET /v1/oidc/userinfo` — userinfo 端点（access-token 授权）

### Minecraft 身份

当 Mojang 已验证的正版玩家在 online-mode 绕过路径上被服务时，模组可解析某 Mojang UUID 是否绑定到
BeaconAuth 账户，以及应如何处理其身份：

- `GET /v1/minecraft/lookup?uuid=<mojangUuid>` — 使用 `X-Minecraft-Auth` 共享密钥
  （`MINECRAFT_LOOKUP_SECRET`）认证。返回 `{ bound, identity_mode, user_subject,
  textures_value, textures_signature }`。
- `GET /v1/minecraft/identity-mode` — 当前用户实际生效的身份偏好。
- `POST /v1/minecraft/identity-mode` — 设置当前用户的偏好（`mojang`/`legacy`）。

### OAuth

- `POST /v1/oauth/start`
- `POST /v1/oauth/link/start`
- `GET /v1/oauth/callback`

支持的提供商：`github`、`google`、`microsoft`（Entra ID）以及 `minecraft`（Microsoft
consumer + Xbox，复用 `MICROSOFT_CLIENT_ID`/`MICROSOFT_CLIENT_SECRET` 凭据）。`minecraft`
提供商将真实的 Mojang UUID 绑定为提供商身份。

### Passkeys（WebAuthn）

- `POST /v1/passkey/register/start`
- `POST /v1/passkey/register/finish`
- `POST /v1/passkey/auth/start`
- `POST /v1/passkey/auth/finish`
- `POST /v1/passkey/delete`
- `GET /v1/passkey/list`
- `DELETE /v1/passkey/{id}`

### 身份

- `GET /v1/identities`
- `DELETE /v1/identities/{id}`

### 配置与 JWKS

- `GET /v1/config`
- `GET /.well-known/jwks.json`

### 管理

- `POST /v1/admin/migrations/up`

## 说明

- 会话端点会设置 HttpOnly 的访问/刷新 Cookie。
- JWT 使用 ES256 签名，并通过 JWKS 发布。
- 部分端点需要已认证会话。

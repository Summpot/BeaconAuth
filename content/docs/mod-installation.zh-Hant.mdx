## 伺服器端安裝

1. 從你找到 BeaconAuth 的發布平台檔案頁下載相符的 mod jar。
   - CurseForge：在 Files 頁選擇與你的 Minecraft 版本和載入器相符的 jar。
   - Modrinth：在 Versions 頁選擇與你的 Minecraft 版本和載入器相符的 jar。
   - Fabric：`beaconauth-fabric-*.jar`
   - Forge：`beaconauth-forge-*.jar`
   - NeoForge：`beaconauth-neoforge-*.jar`
2. 將 jar 放入伺服器的 `mods/` 目錄。
3. 重新啟動伺服器。

## 用戶端安裝

1. 從同一發布平台下載與伺服器相同的 mod jar。
2. 放入用戶端的 `mods/` 目錄。
3. 啟動遊戲並在提示時完成驗證。

## 支援版本

本儲存庫提供 Minecraft 1.19.2、1.20.1、1.21.1、1.21.8 的 loaders（見 `modSrc/`）。

## Mod 設定

第一次啟動伺服器後，會生成設定檔於:

- `config/beaconauth-server.toml`

範例設定:

```toml
[authentication]
# Base URL of your authentication server
# Example: https://beaconauth.pages.dev (development) or https://auth.example.com (production)
# WARNING: Always use HTTPS in production!
base_url = "https://beaconauth.pages.dev"

# JWKS (JSON Web Key Set) URL for JWT signature verification (fallback)
# Usually: <base_url>/.well-known/jwks.json
# Empty means: derive from base_url
jwks_url = ""

[jwt]
# Expected JWT audience (aud claim)
audience = "minecraft-client"

[jku]
# JWT JWKS Discovery (JKU)
# If allowed_host_patterns is non-empty and the JWT has a 'jku' header, BeaconAuth will fetch keys from that JWKS URL.
# Security: You MUST restrict allowed hosts to avoid SSRF.
# When enabled, JKU ALWAYS requires https://.
# Empty means: JKU disabled (BeaconAuth will ignore token 'jku' and only use authentication.jwks_url).
allowed_host_patterns = "beaconauth.pages.dev, *.beaconauth.pages.dev"

[behavior]
# If true: Players with verified Mojang sessions may continue without the BeaconAuth web flow when server is in online-mode
bypass_if_online_mode_verified = true
# If true: Modded clients MUST authenticate when server is offline-mode
force_auth_if_offline_mode = true
# Only applies when force_auth_if_offline_mode is true
# If true: offline-mode vanilla clients (without BeaconAuth mod) are allowed in.
allow_vanilla_offline_clients = true
# 舊版離線身份模式（用於遷移既有的 offline-mode 伺服器）：
# - 若為 true：每個 BeaconAuth 帳戶會被對應到其首次認證登入時聲明的離線 UUID（"OfflinePlayer:<名稱>"）
#   並從此固定使用該身份。
# - 世界資料（playerdata/、stats/、advancements/）不需改名即可保留。
# - 對應關係按世界儲存於 <世界目錄>/beaconauth-identities.json。
# - 安全提示：身份綁定首次登入時的使用者名稱，之後以相同名稱註冊的帳戶會對應到同一 UUID。適用於小型伺服器。
use_legacy_offline_uuids = false
# 若 Mojang 已驗證（正版）玩家綁定到 BeaconAuth 帳戶，且其身份偏好為 “legacy”，
# 則在 online-mode 繞過時將他們對應回舊版離線 UUID，以保留世界資料。需要下方的查詢密鑰。
# 留空（預設）則正版玩家繼續使用 Mojang UUID。
minecraft_lookup_secret = ""
# 僅在設定了 minecraft_lookup_secret 時生效：在 online-mode 繞過時啟用關聯正版
# 的舊版身分解析。建議設為 true。
resolve_linked_premium_legacy = true
```

### 注意

- `authentication.base_url` 用於建立登入 URL 與預期 JWT issuer（`iss`）。
- `authentication.jwks_url` 為空時，預設使用 `${base_url}/.well-known/jwks.json`。
- `jku.allowed_host_patterns` 是逗號/空白分隔的 allowlist。支援模式:
  - `example.com`, `*.example.com`
  - 不支援: 單獨的 `*` 或字串中間通配（例如 `auth*.example.com`）

### 遷移既有的 offline-mode 伺服器（舊版離線身分）

1. 啟用 `behavior.use_legacy_offline_uuids = true`，並保持伺服器 offline-mode。
2. 每個玩家首次透過 BeaconAuth 登入時，模組會將該帳戶綁定到離線 UUID（`OfflinePlayer:<名稱>`），
   並寫入 `<世界目錄>/beaconauth-identities.json`，現有 `playerdata/`、`stats/`、`advancements/`
   不需改名即可繼續使用。
3. 若要規劃遷移，請執行 `/beaconauth unmigrated`（權限等級 2）。它會列出 `playerdata/` 中
   尚未被任何 BeaconAuth 帳戶認領的每個離線檔案（盡可能顯示玩家名稱）；伺服器啟動時也會在
   日誌中記錄未遷移總數。
4. 舊版離線身分只能被認領一次：如果之後有其他 BeaconAuth 帳戶用相同遊戲名稱登入，登入會被
   拒絕並給出明確提示，而不是靜默綁定該身分。
5. 誤操作補救：伺服器管理員（權限等級 2）可用
   `/beaconauth transfer-identity <遊戲名稱> <BeaconAuth使用者名稱>` 轉移身分。
6. 所有人遷移完成後對應關係仍會生效；之後再關閉該模式會讓帳戶回到穩定的 per-account UUID
   （新世界資料，不再關聯舊資料）。

### 遷移伺服器上的正版玩家（關聯 Minecraft 帳戶）

如果你遷移的部分玩家其實是**正版**（他們擁有真實的 Minecraft 帳戶），你可以讓他們在不需網頁登入的情況下
繼續使用已遷移的世界資料：

1. 在 BeaconAuth 網頁界面中，玩家關聯其 Minecraft 帳戶（Microsoft/Xbox 登入），並將其身份偏好設定為
   **舊版離線身分**（保留世界資料）。
2. 在伺服器上，將 `behavior.minecraft_lookup_secret` 設定為你已在 BeaconAuth 伺服器上設定的共享密鑰
   （`MINECRAFT_LOOKUP_SECRET`）。
3. 當 Mojang 已驗證的正版玩家加入（online-mode 繞過）時，模組會向 BeaconAuth 伺服器查詢該 Mojang UUID
   是否綁定到偏好為 “legacy” 的帳戶。若是，玩家會被對應到該帳戶在本世界擁有的舊版離線 UUID，並重放快取的
   Mojang `textures` 屬性，從而在保留世界資料的**同時**保留真實的皮膚/披風。

注意：

- 該查詢只會回答「此 Mojang UUID 是否已綁定，以及模組應如何解析其身份」——不會暴露任何私人資料。
- 若身份偏好為 “Mojang UUID”（預設）或該 UUID 未綁定，則正版玩家繼續使用 Mojang UUID（原版行為）。
- 若玩家的舊版離線身分已被另一個 BeaconAuth 帳戶認領，該正版玩家繼續使用 Mojang UUID，並記錄一條警告
  （絕不靜默覆寫）。
- `resolve_linked_premium_legacy = false` 即使設定了密鑰也會停用此解析。

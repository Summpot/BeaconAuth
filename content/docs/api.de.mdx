## Basis-Pfade

Die API wird bereitgestellt unter:

- `/v1/*` (direkt)
- `/api/v1/*` (wenn unter `/api` gemountet)

## Kernendpunkte

### Sessions

- `POST /v1/login`
- `POST /v1/register`
- `POST /v1/refresh`
- `POST /v1/logout`
- `GET /v1/user/me`
- `GET /v1/user/me/avatar`
- `POST /v1/user/change-password`
- `POST /v1/user/change-username`
- `POST /v1/user/profile`

Beispiel: `POST /v1/login`

```json
{
  "username": "player123",
  "password": "secure_password"
}
```

### Minecraft-Authentifizierung (OIDC)

Das Minecraft-Mod verwendet einen standardmäßigen OIDC-Autorisierungscode- + PKCE-Flow:

- `GET /.well-known/openid-configuration` — OIDC-Discovery
- `GET /v1/oidc/authorize` — Autorisierungs-Endpunkt (das Mod öffnet ihn über die Login-UI)
- `POST /v1/oidc/complete` — die SPA schließt die Autorisierung ab und leitet zum Mod zurück
- `POST /v1/oidc/token` — Token-Endpunkt (ohne Client-Secret, PKCE-gebunden)
- `GET /v1/oidc/userinfo` — Userinfo-Endpunkt (per Access-Token autorisiert)

### Minecraft-Identität

Wenn ein Mojang-verifizierter Premium-Spieler über den Online-Mode-Bypass-Pfad bedient wird, kann
das Mod auflösen, ob eine Mojang-UUID an ein BeaconAuth-Konto gebunden ist und wie seine Identität
zu behandeln ist:

- `GET /v1/minecraft/lookup?uuid=<mojangUuid>` — authentifiziert mit dem gemeinsamen Secret
  `X-Minecraft-Auth` (`MINECRAFT_LOOKUP_SECRET`). Liefert `{ bound, identity_mode, user_subject,
  textures_value, textures_signature }`.
- `GET /v1/minecraft/identity-mode` — die aktuelle effektive Identitätspräferenz des Benutzers.
- `POST /v1/minecraft/identity-mode` — setzt die Präferenz des aktuellen Benutzers (`mojang`/`legacy`).

### OAuth

- `POST /v1/oauth/start`
- `POST /v1/oauth/link/start`
- `GET /v1/oauth/callback`

Unterstützte Provider: `github`, `google`, `microsoft` (Entra ID) sowie `minecraft` (Microsoft
Consumer + Xbox, Wiederverwendung der `MICROSOFT_CLIENT_ID`/`MICROSOFT_CLIENT_SECRET`-Anmeldedaten).
Der `minecraft`-Provider bindet die echte Mojang-UUID als Provider-Identität.

### Passkeys (WebAuthn)

- `POST /v1/passkey/register/start`
- `POST /v1/passkey/register/finish`
- `POST /v1/passkey/auth/start`
- `POST /v1/passkey/auth/finish`
- `POST /v1/passkey/delete`
- `GET /v1/passkey/list`
- `DELETE /v1/passkey/{id}`

### Identitäten

- `GET /v1/identities`
- `DELETE /v1/identities/{id}`

### Konfiguration und JWKS

- `GET /v1/config`
- `GET /.well-known/jwks.json`

### Admin

- `POST /v1/admin/migrations/up`

## Hinweise

- Session-Endpunkte setzen HttpOnly-Cookies für Access/Refresh Tokens.
- JWTs werden mit ES256 signiert und via JWKS veröffentlicht.
- Einige Endpunkte erfordern eine authentifizierte Session.

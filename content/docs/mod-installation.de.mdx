## Server-Installation

1. Lade das passende Mod-Jar von der Dateiseite der Plattform herunter, auf der du BeaconAuth gefunden hast.
   - CurseForge: Verwende den Files-Tab und wähle das Jar für deine Minecraft-Version und deinen Loader.
   - Modrinth: Verwende den Versions-Tab und wähle das Jar für deine Minecraft-Version und deinen Loader.
   - Fabric: `beaconauth-fabric-*.jar`
   - Forge: `beaconauth-forge-*.jar`
   - NeoForge: `beaconauth-neoforge-*.jar`
2. Lege das Jar in das Server-Verzeichnis `mods/`.
3. Starte den Server neu.

## Client-Installation

1. Lade dasselbe Mod-Jar wie auf dem Server von derselben Veröffentlichungsplattform herunter.
2. Lege es in das Client-Verzeichnis `mods/`.
3. Starte das Spiel und authentifiziere dich, wenn du dazu aufgefordert wirst.

## Unterstützte Versionen

Das Repository liefert Loader für Minecraft 1.19.2, 1.20.1, 1.21.1 und 1.21.8 (siehe `modSrc/`).

## Mod-Konfiguration

Nach dem ersten Serverstart wird eine Konfigurationsdatei erzeugt unter:

- `config/beaconauth-server.toml`

Beispielkonfiguration:

```toml
[authentication]
# Base URL of your authentication server
# Example: https://beaconauth.pages.dev (development) or https://auth.example.com (production)
# WARNING: Always use HTTPS in production!
base_url = "https://beaconauth.pages.dev"

# JWKS (JSON Web Key Set) URL for JWT signature verification (fallback)
# Usually: <base_url>/.well-known/jwks.json
# Empty means: derive from base_url
jwks_url = ""

[jwt]
# Expected JWT audience (aud claim)
audience = "minecraft-client"

[jku]
# JWT JWKS Discovery (JKU)
# If allowed_host_patterns is non-empty and the JWT has a 'jku' header, BeaconAuth will fetch keys from that JWKS URL.
# Security: You MUST restrict allowed hosts to avoid SSRF.
# When enabled, JKU ALWAYS requires https://.
# Empty means: JKU disabled (BeaconAuth will ignore token 'jku' and only use authentication.jwks_url).
allowed_host_patterns = "beaconauth.pages.dev, *.beaconauth.pages.dev"

[behavior]
# If true: Players with verified Mojang sessions may continue without the BeaconAuth web flow when server is in online-mode
bypass_if_online_mode_verified = true
# If true: Modded clients MUST authenticate when server is offline-mode
force_auth_if_offline_mode = true
# Only applies when force_auth_if_offline_mode is true
# If true: offline-mode vanilla clients (without BeaconAuth mod) are allowed in.
allow_vanilla_offline_clients = true
# Legacy-Offline-Identitätsmodus (für die Migration eines bestehenden Offline-Mode-Servers):
# - Bei true: Jedes BeaconAuth-Konto wird der Offline-UUID ("OfflinePlayer:<Name>") zugeordnet,
#   die es bei seiner ersten authentifizierten Anmeldung beansprucht hat, und behält diese Identität.
# - Weltdaten (playerdata/, stats/, advancements/) bleiben ohne Umbenennung von Dateien erhalten.
# - Die Zuordnung wird pro Welt in <Weltverzeichnis>/beaconauth-identities.json gespeichert.
# - Sicherheit: Die Identität ist an den bei der ersten Anmeldung verwendeten Namen gebunden.
#   Spätere Konten mit demselben Namen würden derselben UUID zugeordnet. Nur für kleine Server gedacht.
use_legacy_offline_uuids = false
# Wenn ein Mojang-verifizierter (Premium-)Spieler an ein BeaconAuth-Konto gebunden ist und seine
# Identitätseinstellung "legacy" ist, ordne ihn beim Online-Mode-Bypass wieder der Legacy-Offline-UUID zu,
# damit die Weltdaten erhalten bleiben. Erfordert das unten stehende Lookup-Secret.
# Leer lassen (Standard), um Premium-Spieler auf der Mojang-UUID zu belassen.
minecraft_lookup_secret = ""
# Nur relevant, wenn minecraft_lookup_secret gesetzt ist: aktiviere die verknüpfte Premium-Legacy-Auflösung
# beim Online-Mode-Bypass. Empfohlen: true.
resolve_linked_premium_legacy = true
```

### Hinweise

- `authentication.base_url` wird zum Aufbau der Login-URLs und als erwarteter JWT-Issuer (`iss`) genutzt.
- `authentication.jwks_url` ist leer standardmäßig `${base_url}/.well-known/jwks.json`.
- `jku.allowed_host_patterns` ist eine kommagetrennte/leerzeichengetrennte Allowlist. Unterstützte Muster:
  - `example.com`, `*.example.com`
  - Nicht unterstützt: nacktes `*` oder Wildcards mitten im String wie `auth*.example.com`

### Migration eines bestehenden Offline-Mode-Servers (Legacy-Identitäten)

1. Aktiviere `behavior.use_legacy_offline_uuids = true` und behalte den Server im Offline-Modus.
2. Bei der ersten BeaconAuth-Anmeldung eines Spielers bindet das Mod das Konto an die Offline-UUID
   (`OfflinePlayer:<Name>`) und schreibt `<Weltverzeichnis>/beaconauth-identities.json`, sodass
   vorhandene `playerdata/`, `stats/` und `advancements/` ohne Umbenennung weiter funktionieren.
3. Zur Migrationsplanung: `/beaconauth unmigrated` (Berechtigungsstufe 2) listet jedes Offline-Profil
   in `playerdata/`, das noch von keinem BeaconAuth-Konto beansprucht wurde (mit Spielername, sofern
   verfügbar); der Server protokolliert die Gesamtzahl auch beim Start.
4. Eine Legacy-Identität kann nur einmal beansprucht werden: Versucht danach ein anderes
   BeaconAuth-Konto mit demselben Namen zu loggen, wird die Anmeldung mit einer klaren Meldung
   abgelehnt, statt die Identität still zu übernehmen.
5. Notfalllösung bei Fehlern: Ein Server-Operator (Berechtigungsstufe 2) kann eine Identität mit
   `/beaconauth transfer-identity <MinecraftName> <BeaconAuthBenutzername>` übertragen.
6. Nach Abschluss der Migration bleibt die Zuordnung aktiv; ein späteres Deaktivieren des Modus
   wechselt die Konten zurück auf stabile Per-Account-UUIDs (neue Weltdaten, nicht die alten).

### Premium-Spieler auf einem migrierten Server (verknüpfte Minecraft-Konten)

Wenn einige deiner migrierten Spieler tatsächlich **Premium**-Spieler sind (sie besitzen ein echte
Minecraft-Konto), kannst du ihnen erlauben, ihre migrierten Weltdaten ohne Web-Login weiterzunutzen:

1. In der BeaconAuth-Weboberfläche verknüpfen die Spieler ihr Minecraft-Konto (Microsoft/Xbox-Anmeldung)
   und setzen ihre Identitätseinstellung auf **Legacy-Offline-Identität** (Weltdaten erhalten).
2. Setze auf dem Server `behavior.minecraft_lookup_secret` auf das gemeinsame Secret, das du auf
   dem BeaconAuth-Server konfiguriert hast (`MINECRAFT_LOOKUP_SECRET`).
3. Wenn sich ein Mojang-verifizierter Premium-Spieler anmeldet (Online-Mode-Bypass), fragt das Mod
   den BeaconAuth-Server, ob diese Mojang-UUID an ein Konto mit der "legacy"-Einstellung gebunden ist.
   Ist das der Fall, wird der Spieler der Legacy-Offline-UUID zugeordnet, die das Konto auf dieser
   Welt besitzt, und die gecachte Mojang-`textures`-Eigenschaft wird wiedergegeben, sodass er seine
   Weltdaten **und** seine echte Skin/Cape behält.

Hinweise:

- Das Lookup beantwortet nur "Ist diese Mojang-UUID gebunden, und wie soll das Mod ihre Identität
  auflösen" — es legt keine privaten Daten offen.
- Wenn die Identitätseinstellung "Mojang-UUID" (Standard) ist oder die UUID nicht gebunden ist,
  behält der Premium-Spieler einfach die Mojang-UUID (Vanilla-Verhalten).
- Wenn die Legacy-Offline-Identität des Spielers bereits von einem anderen BeaconAuth-Konto
  beansprucht wurde, behält der Premium-Spieler die Mojang-UUID und eine Warnung wird protokolliert
  (niemals still überschreiben).
- `resolve_linked_premium_legacy = false` deaktiviert diese Auflösung auch bei gesetztem Secret.

## 모노레포 구조

- `crates/beacon`: Rust 서버 바이너리 및 CLI (serve, migrate, 사용자 관리)
- `crates/beacon-core`: 런타임 전반에서 사용하는 공유 모델/암호화/OAuth 헬퍼
- `crates/beacon-worker`: Cloudflare Worker (wasm32) API 런타임
- `crates/beacon-lambda`: 서버리스 런타임 (AWS Lambda 또는 호환)
- `crates/beacon-passkey`: WebAuthn/패스키 로직
- `crates/beacon-frontend-embed`: 임베더블 프론트엔드 유틸리티
- `crates/entity` 및 `crates/migration`: SeaORM 엔티티와 DB 마이그레이션
- `src/`: React 웹 UI (라우트, 컴포넌트, 스타일)
- `modSrc/`: Minecraft 모드 (Kotlin/Gradle, Architectury) - Fabric/Forge/NeoForge 타깃
- `messages/`, `src/paraglide/`, `project.inlang/`: 로컬라이제이션 자산 및 도구
- `content/docs/`: Fumadocs 문서
- `wrangler*.jsonc`: Cloudflare Pages/Worker 배포 설정

## 런타임 구성 요소

- **인증 서버 (Rust)**: 로그인/회원가입/OAuth/패스키를 처리하고 ES256 JWT 발급
- **Web UI (React)**: 로그인, 회원가입, 설정, 프로필, OAuth 완료 플로우
- **Minecraft 모드**: PKCE 기반 로그인을 수행하고 게임 내 접근을 위해 JWT 검증
- **Cloudflare Worker (선택)**: 서버리스 배포를 위한 엣지 API 런타임

## 인증 플로우 (상위 수준)

1. 사용자가 Web UI에서 인증 (비밀번호, OAuth, 또는 패스키)
2. 서버가 액세스/리프레시 토큰 발급 (ES256 JWT + 리프레시 쿠키)
3. 모드가 PKCE 플로우를 통해 Minecraft 전용 JWT 요청
4. 게임 서버가 JWKS 엔드포인트를 사용해 JWT 검증

## 스토리지와 상태

- **기본 서버 스토리지**: SQLite (`DATABASE_URL` 로 설정)
- **서버리스 스토리지**: Worker 배포에서 `LIBSQL_URL` 을 통한 libSQL/Turso
- **임시 세레모니 상태**: 멀티 인스턴스 WebAuthn 플로우를 위한 선택적 Redis (`REDIS_URL`)

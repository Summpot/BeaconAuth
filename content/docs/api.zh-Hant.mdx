## Base paths

API 提供於:

- `/v1/*`（直接）
- `/api/v1/*`（掛載在 `/api` 下時）

## 核心端點

### Sessions

- `POST /v1/login`
- `POST /v1/register`
- `POST /v1/refresh`
- `POST /v1/logout`
- `GET /v1/user/me`
- `GET /v1/user/me/avatar`
- `POST /v1/user/change-password`
- `POST /v1/user/change-username`
- `POST /v1/user/profile`

範例：`POST /v1/login`

```json
{
  "username": "player123",
  "password": "secure_password"
}
```

### Minecraft 驗證（OIDC）

Minecraft mod 使用標準的 OIDC authorization-code + PKCE 流程：

- `GET /.well-known/openid-configuration` — OIDC discovery
- `GET /v1/oidc/authorize` — 授權端點（mod 透過登入界面開啟）
- `POST /v1/oidc/complete` — SPA 完成授權，重新導向回 mod
- `POST /v1/oidc/token` — token 端點（無 client secret，PKCE 綁定）
- `GET /v1/oidc/userinfo` — userinfo 端點（以 access token 授權）

### Minecraft 身分

當 Mojang 已驗證的正版玩家在 online-mode 繞過路徑上被服務時，mod 可解析某 Mojang UUID 是否綁定到
BeaconAuth 帳戶，以及應如何處理其身份：

- `GET /v1/minecraft/lookup?uuid=<mojangUuid>` — 使用 `X-Minecraft-Auth` 共享密鑰
  （`MINECRAFT_LOOKUP_SECRET`）驗證。回傳 `{ bound, identity_mode, user_subject,
  textures_value, textures_signature }`。
- `GET /v1/minecraft/identity-mode` — 目前使用者實際生效的身份偏好。
- `POST /v1/minecraft/identity-mode` — 設定目前使用者的偏好（`mojang`/`legacy`）。

### OAuth

- `POST /v1/oauth/start`
- `POST /v1/oauth/link/start`
- `GET /v1/oauth/callback`

支援的 providers：`github`、`google`、`microsoft`（Entra ID）以及 `minecraft`（Microsoft
consumer + Xbox，重用 `MICROSOFT_CLIENT_ID`/`MICROSOFT_CLIENT_SECRET` 憑證）。`minecraft`
provider 會將真實的 Mojang UUID 綁定為 provider identity。

### Passkeys（WebAuthn）

- `POST /v1/passkey/register/start`
- `POST /v1/passkey/register/finish`
- `POST /v1/passkey/auth/start`
- `POST /v1/passkey/auth/finish`
- `POST /v1/passkey/delete`
- `GET /v1/passkey/list`
- `DELETE /v1/passkey/{id}`

### Identities

- `GET /v1/identities`
- `DELETE /v1/identities/{id}`

### 設定與 JWKS

- `GET /v1/config`
- `GET /.well-known/jwks.json`

### Admin

- `POST /v1/admin/migrations/up`

## Notes

- Session 端點會以 HttpOnly cookies 設定 access/refresh tokens。
- JWT 以 ES256 簽章並透過 JWKS 發佈。
- 部分端點需要已驗證的 session。

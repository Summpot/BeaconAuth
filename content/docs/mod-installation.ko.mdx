## 서버 설치

1. BeaconAuth를 찾은 배포 플랫폼의 파일 페이지에서 알맞은 모드 jar를 다운로드합니다.
   - CurseForge: Files 탭에서 Minecraft 버전과 로더에 맞는 jar를 선택합니다.
   - Modrinth: Versions 탭에서 Minecraft 버전과 로더에 맞는 jar를 선택합니다.
   - Fabric: `beaconauth-fabric-*.jar`
   - Forge: `beaconauth-forge-*.jar`
   - NeoForge: `beaconauth-neoforge-*.jar`
2. 서버의 `mods/` 디렉터리에 jar를 넣습니다.
3. 서버를 재시작합니다.

## 클라이언트 설치

1. 서버와 동일한 모드 jar를 같은 배포 플랫폼에서 다운로드합니다.
2. 클라이언트의 `mods/` 디렉터리에 넣습니다.
3. 게임을 실행하고, 프롬프트가 뜨면 인증합니다.

## 지원 버전

이 저장소는 Minecraft 1.19.2, 1.20.1, 1.21.1, 1.21.8 용 로더를 제공합니다(`modSrc/` 참고).

## 모드 구성

서버를 처음 실행하면 다음 위치에 설정 파일이 생성됩니다:

- `config/beaconauth-server.toml`

예시 설정:

```toml
[authentication]
# Base URL of your authentication server
# Example: https://beaconauth.pages.dev (development) or https://auth.example.com (production)
# WARNING: Always use HTTPS in production!
base_url = "https://beaconauth.pages.dev"

# JWKS (JSON Web Key Set) URL for JWT signature verification (fallback)
# Usually: <base_url>/.well-known/jwks.json
# Empty means: derive from base_url
jwks_url = ""

[jwt]
# Expected JWT audience (aud claim)
audience = "minecraft-client"

[jku]
# JWT JWKS Discovery (JKU)
# If allowed_host_patterns is non-empty and the JWT has a 'jku' header, BeaconAuth will fetch keys from that JWKS URL.
# Security: You MUST restrict allowed hosts to avoid SSRF.
# When enabled, JKU ALWAYS requires https://.
# Empty means: JKU disabled (BeaconAuth will ignore token 'jku' and only use authentication.jwks_url).
allowed_host_patterns = "beaconauth.pages.dev, *.beaconauth.pages.dev"

[behavior]
# If true: Players with verified Mojang sessions may continue without the BeaconAuth web flow when server is in online-mode
bypass_if_online_mode_verified = true
# If true: Modded clients MUST authenticate when server is offline-mode
force_auth_if_offline_mode = true
# Only applies when force_auth_if_offline_mode is true
# If true: offline-mode vanilla clients (without BeaconAuth mod) are allowed in.
allow_vanilla_offline_clients = true
# 레거시 오프라인 ID 모드 (기존 offline-mode 서버 마이그레이션용):
# - true인 경우: 각 BeaconAuth 계정은 첫 인증 로그인 시 주장한 오프라인 UUID("OfflinePlayer:<이름>")에
#   매핑되며 이후 해당 ID가 고정됩니다.
# - 월드 데이터(playerdata/, stats/, advancements/)는 파일 이름 변경 없이 보존됩니다.
# - 매핑은 월드별로 <월드 디렉터리>/beaconauth-identities.json에 저장됩니다.
# - 보안: ID는 첫 로그인 시 사용한 이름에 묶이므로, 나중에 같은 이름으로 가입한 계정도
#   동일한 UUID로 매핑됩니다. 소규모 서버용입니다.
use_legacy_offline_uuids = false
# Mojang 검증(정품) 플레이어가 BeaconAuth 계정에 바인딩되어 있고 ID 선호가 "legacy"인 경우,
# 온라인 모드 우회 시 레거시 오프라인 UUID로 다시 매핑하여 월드 데이터를 보존합니다.
# 아래의 lookup secret이 필요합니다.
# 비워 두면(기본값) 정품 플레이어는 Mojang UUID를 유지합니다.
minecraft_lookup_secret = ""
# minecraft_lookup_secret이 설정된 경우에만 유효: 온라인 모드 우회 시 연결된 정품 레거시
# 해석을 활성화합니다. true를 권장합니다.
resolve_linked_premium_legacy = true
```

### 참고

- `authentication.base_url` 는 로그인 URL 구성 및 기대 JWT issuer(`iss`)에 사용됩니다.
- `authentication.jwks_url` 이 비어 있으면 `${base_url}/.well-known/jwks.json` 을 기본값으로 사용합니다.
- `jku.allowed_host_patterns` 는 콤마/공백으로 구분된 allowlist 입니다. 지원 패턴:
  - `example.com`, `*.example.com`
  - 지원하지 않음: 단독 `*` 또는 `auth*.example.com` 같은 중간 와일드카드

### 기존 offline-mode 서버 마이그레이션 (레거시 ID)

1. `behavior.use_legacy_offline_uuids = true`를 활성화하고 서버를 offline-mode로 유지합니다.
2. 각 플레이어가 처음 BeaconAuth로 로그인하면 mod가 계정을 오프라인 UUID(`OfflinePlayer:<이름>`)에
   바인딩하고 `<월드 디렉터리>/beaconauth-identities.json`에 저장합니다. 기존 `playerdata/`,
   `stats/`, `advancements/`는 파일 이름 변경 없이 그대로 사용됩니다.
3. 마이그레이션을 계획하려면 `/beaconauth unmigrated`(권한 레벨 2)를 실행하세요. 아직 어떤
   BeaconAuth 계정도 인계받지 않은 `playerdata/`의 각 오프라인 프로필을, 이름을 알 수 있으면
   함께 목록으로 표시합니다. 서버는 시작 시에도 총 개수를 로그로 기록합니다.
4. 레거시 ID는 한 번만 인계받을 수 있습니다. 이후 다른 BeaconAuth 계정이 같은 이름으로 로그인을
   시도하면 조용히 ID를 가져가지 않고 명확한 메시지와 함께 로그인이 거부됩니다.
5. 실수 시 구제 방법: 서버 운영자(권한 레벨 2)는
   `/beaconauth transfer-identity <Minecraft이름> <BeaconAuth사용자이름>`으로 ID를 이전할 수 있습니다.
6. 마이그레이션이 끝난 후에도 매핑은 유지됩니다. 이후 모드를 끄면 계정은 안정적인 per-account
   UUID(새 월드 데이터, 기존 데이터와는 무관)로 돌아갑니다.

### 마이그레이션된 서버의 프리미엄 플레이어 (연결된 Minecraft 계정)

마이그레이션된 플레이어 중 일부가 실제로 **프리미엄**(정식 Minecraft 계정 보유자)인 경우,
웹 로그인 없이 마이그레이션된 월드 데이터를 계속 사용할 수 있습니다.

1. BeaconAuth 웹 UI에서 플레이어는 자신의 Minecraft 계정을 연결(Microsoft/Xbox로 로그인)하고,
   신원 환경설정을 **레거시 오프라인 신원(월드 데이터 보존)**으로 설정합니다.
2. 서버에서 `behavior.minecraft_lookup_secret`을 BeaconAuth 서버에 설정한 공유 비밀키
   (`MINECRAFT_LOOKUP_SECRET`)와 일치시킵니다.
3. Mojang 검증된 프리미엄 플레이어가 접속하면(온라인 모드 바이패스), 모드는 BeaconAuth 서버에 해당
   Mojang UUID가 'legacy' 환경설정의 계정에 연결되어 있는지 질의합니다. 연결된 경우, 플레이어는 이
   월드에서 해당 계정이 소유한 레거시 오프라인 UUID로 매핑되고, 캐시된 Mojang `textures` 속성이 재생되어
   월드 데이터**와** 실제 스킨/망토를 모두 유지합니다.

참고:

- 이 조회는 "이 Mojang UUID가 연결되어 있는지, 모드가 신원을 어떻게 해결해야 하는지"에만 답하며,
  개인 정보를 노출하지 않습니다.
- 신원 환경설정이 "Mojang UUID"(기본값)이거나 UUID가 연결되어 있지 않으면 프리미엄 플레이어는 단순히
  Mojang UUID(바닐라 동작)를 유지합니다.
- 플레이어의 레거시 오프라인 신원이 이미 다른 BeaconAuth 계정에 의해 인계된 경우, 프리미엄 플레이어는
  Mojang UUID를 유지하고 경고가 로그에 기록됩니다(절대 조용히 덮어쓰지 않음).
- `resolve_linked_premium_legacy = false`로 설정하면 비밀키가 설정되어 있어도 이 해결이 비활성화됩니다.
